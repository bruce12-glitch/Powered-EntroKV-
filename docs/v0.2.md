# Page EntroKV v0.2: capture and data contract

The browser analyzes normalized attention observations. The optional Python capture CLI runs
models locally. Neither path mutates a model's KV cache or measures generation quality.

## Attention bundles

```json
{
  "schema_version": "2.0",
  "kind": "attention_bundle",
  "name": "Experiment name",
  "source": "imported",
  "metadata": {},
  "observations": [
    {
      "id": "layer-000",
      "layer": 0,
      "trace": {
        "schema_version": "1.0",
        "query_heads": 1,
        "kv_heads": 1,
        "sink_size": 0,
        "attention": [[0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625,0.0625]]
      }
    }
  ]
}
```

This is a complete importable uniform example. Source is an importer-provided label; it is not
authenticated. Allowed labels: `synthetic`, `model_capture`, `random_weight_model`, and `imported`.
Unknown labels become `imported`. Observation IDs are unique strings up to 100 characters; layer
indices are integers 0–255. Multiple observations of a layer are allowed with distinct IDs.

All observations share the same context length and original token positions. Optional `token_ids`
and `token_text` have one entry per token. Token IDs are nonnegative safe integers; decoded token
strings are at most 256 characters. Decoding one token at a time may not reconstruct Unicode
or text exactly. IDs alone may reveal prompt content.

Each trace has 1–64 query heads, query_heads divisible by kv_heads, 16–8,192 tokens, and at most
262,144 attention values. Heads are contiguous within each KV group. Rows are finite nonnegative
probabilities summing to 1 within 1e-5; imports are never silently normalized.

Bundles hold 1–128 observations and at most 1,048,576 attention values in total. JSON imports are
limited to 32 MiB. The legacy single-layer importer retains an 8 MiB limit. Metadata is bounded
(depth 6, up to 128 keys/object, 2,048 entries/array, 2,000 characters/string). Import sanitizes
unknown fields and label lengths before manifest hashing.

## Capture semantics

Use `dist/assets/capture_attention.py`, with the pinned requirements alongside it. Supported
model type: Qwen2, including Qwen2.5 model IDs using that architecture. The model and tokenizer
share a requested revision; prefer an immutable commit SHA. Resolved hashes are recorded when
available, but a moving revision may resolve differently on later runs. Remote model code is disabled.

One unpadded prompt is tokenized as raw text with tokenizer special tokens; the CLI does not
apply an instruction/chat template. If too long, it retains the first max_tokens tokens and
records/reports truncation. The final query window is 1–32 rows. The prefix uses SDPA with a KV
cache; the suffix uses eager attention and original absolute positions. All layers execute.
Temporary attention storage is bounded by L × H_Q × Q × T, capped at 67,108,864 elements;
this is not an upper bound on total model RAM or VRAM.

The selected layer tensors are cast to Float64 and averaged across the observed query rows.
Each resulting head row is explicitly normalized; the maximum original mean-row sum error is
recorded per layer. Errors above 0.02 abort capture. Causal rows in the window can attend to
different prefixes; this aggregation is a stated observation strategy, not future-query evidence.

Capture metadata records the model, revisions, seed, dtype/device, library versions, prompt-file
SHA-256, aggregation/normalization, truncation, and capture script SHA-256. A code revision is
recorded only when the script is tracked and unchanged in a git checkout. Seeded evaluation does
not assert cross-device bitwise determinism. Existing output files are refused.

`--smoke-test` uses a tiny random-weight Qwen2 CPU model and random token IDs, without a pretrained
download. The bundled `dist/assets/qwen2-smoke.json` is labeled accordingly. It is a mechanical
example, not a pretrained benchmark or reproduction of manuscript pilot observations.

## Configuration and metrics

Configurations have numeric `retention` in (0,100], integer `blockSize` in [1,512], numeric `tau`
in [0.05,10], and boolean `isolate`. K = max(1, floor(ceil(T/B) × retention/100)). Both weighted
and mean policies retain K pages per group; ties use ascending page index.

`reference_mass` sums the retained probabilities under the arithmetic mean of the **original
sibling head rows**, identically for every policy. It is not the weighted policy's own pooled
mass, and is not a task-quality metric. Displayed aggregate points weight each observed
layer–group pair equally. Independent-head unions can exceed the shared budget.

Realized retention is selected page count / total page count, including final-page padding.
Jaccard overlap uses valid original token positions, excluding padding, so comparisons with
different block sizes remain meaningful. Captured layers alone do not establish all-layer behavior.

## Full research manifests and checksums

Full exports use schema 2.0 and kind `page_entrokv_research_manifest` with `input`, `configs`,
`results`, `checksums`, engine version, creation time, and provenance. They preserve every input
row plus selected indices, entropies, weights, and diagnostics. Detailed page scores are recomputed
from input. The provenance code_revision identifies the code-bearing release commit; a later
metadata-only commit may stamp that field. This is separate from the hosting source commit.

Input/config/result SHA-256 digests use UTF-8 JSON with recursively sorted object keys and
JavaScript JSON number/string serialization. Array order is preserved. This is a project-specific
serialization, not a general cross-language JSON canonicalization standard. The bundle digest
covers the validated/sanitized bundle, including retained metadata and optional token labels.

Optional per-observation `attention_sha256` uses a Python/JavaScript binary wire format:

1. UTF-8 magic `PageEntroKV/attention-v2` followed by one zero byte.
2. Four unsigned 32-bit little-endian integers: query_heads, kv_heads, sink_size, token_count.
3. Head-major probabilities, each as IEEE 754 Float64 little-endian.

These attention digests exclude metadata and token labels. The full bundle digest covers those
validated fields. Import verifies supplied attention hashes and manifest digests before analysis.
It then recomputes and compares the result digest, reporting a match or difference. Mismatches
must be investigated rather than treated as successful reproduction. Different arithmetic or
engine versions can change results near ties. SHA-256 needs HTTPS or localhost in the browser.

Checksums detect inconsistent content. Anyone can edit data and recompute a checksum; these
values do not authenticate authors, model identity, or correctness of research claims.

V1 traces upgrade to imported one-observation bundles. V1 full manifests also restore their
recorded configuration, without claiming cryptographic integrity for the old format. V0.1
lightweight local snapshots omit input arrays and cannot restore imported traces on their own.

## Local projects and verification scope

Save project stores the full manifest in the `page-entrokv-projects` IndexedDB database, up to
20 projects. Opening verifies input and recomputes results. Browser storage is origin-specific
and can be cleared; a downloaded manifest is the portable research record. Imports are not uploaded.

The integration tests compare bounded capture against full eager final-query observations on a
tiny random Qwen2 CPU model (`rtol=1e-5`, `atol=1e-7`). The numerical suite checks independent
analytical invariants, Python/JavaScript parity, binary hashes, manifests, and policy diagnostics.
Pretrained CUDA capture, compressed generation, physical allocation, and serving performance are
outside this release's validated scope. Future vLLM work needs a pinned current backend audit,
position-correct attention, physical storage release, and matched end-to-end benchmarks.
